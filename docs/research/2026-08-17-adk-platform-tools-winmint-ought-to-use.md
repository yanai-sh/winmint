# Research: ADK / WinPE platform tools WinMint ought to use

**Date:** 2026-08-17  
**Question:** Besides `winpeshl.ini` `[LaunchApp]` (already the answer for the WinPE apply console — [#119](https://github.com/yanai-sh/winmint/issues/119)), which modern documented Microsoft / Windows / ADK facilities does Learn name that WinMint currently approximates with `cmd`, `dism.exe` CLI, custom C#, or v1 leftovers?  
**Scope:** Other product seams only. Do **not** hunt alternatives to winpeshl. Do **not** recommend Setup GUI as the install engine.  
**Method:** Microsoft Learn MCP was not available in this session. Queries ran through `npx @microsoft/learn-cli search` / `fetch` against learn.microsoft.com only. No invented APIs.

## 3. Ranked “ought to use” (other parts only)

**None at #119 quality.** After excluding winpeshl / the WinPE apply console, Learn does not name a second unused inbox/ADK facility that WinMint is approximating with the wrong host.

What this hunt found instead:

- Host ImageServicing already calls the documented tool (`dism.exe`). The DISM API and WimgApi are the same stack in C, not a missing opcode.
- OOBE answers already use the documented contract (unattend `oobeSystem` + Panther `unattend.xml`). WCD/PPKG, Oobe.xml, CloudExperienceHost, `Apply-Unattend`, and `Autounattend.xml`-for-Setup are different products or different engines.
- SetupComplete, specialize `RunSynchronous`, reserved-storage DISM, oscdimg, and Hyper-V `New-VM` are already the named tools.
- DMA `DeviceRegion` has **no** Learn manufacturing setting. `reg add` is not a leftover; it is the latch because International-Core does not expose that key.

The only documented *optional* hide that is not winpeshl — SetupComplete `wscript` + `WshShell.Run(..., 0, True)` — is already in [2026-08-16](2026-08-16-clean-hands-off-oobe.md). It does not replace SetupComplete; it only hides the child. Not a new issue.

Learn also says to delete the cached `%WINDIR%\panther` answer file before customer delivery (passwords persist). That is hygiene after OOBE consumes the file, not a platform tool to switch to. Do not delete before `oobeSystem` has run.

## 4. Explicit rejects

- **Setup GUI / `setup.exe` / `/legacy` as the install engine.** WinPE apply stays the product. `Autounattend.xml` search order is Setup’s contract, not apply’s.
- **Guest pwsh product runtime** / v1 `WinMint.ps1` / DISM PowerShell cmdlets in the guest / `Set-WindowsReservedStorageState` / `Set-WinHomeLocation` as product.
- **`SkipMachineOOBE` / `SkipUserOOBE`.** Automate OOBE; don’t skip it.
- **Shell Launcher / Assigned Access before OOBE** (image not deployable; OOBE UI needs Explorer). **After OOBE** as a kiosk replacement for Supervisor→Explorer.
- **CopyPE / MakeWinPEMedia** as Output ISO (ADK WinPE add-on, not user Source ISO).
- **Sysprep generalize** (apply-from-ISO, not capture).
- **WCD / `.ppkg`** as a substitute for unattend + Supervisor.
- **Oobe.xml** OEM chrome; **CloudExperienceHost** skip (no API).
- **`Use-WindowsUnattend` / `DISM /Apply-Unattend`** for oobeSystem/specialize.
- **FirstLogonCommands** for reserved-storage / machine-setup (wrong IL).
- **DISM API / WimgApi** as a host-kernel rewrite, or **DismAPI.dll** in the guest (ADK host requirement).
- **Peer Splash.exe**; **invented DeviceRegion unattend**.
- **winpeshl alternatives** — out of scope; [#119](https://github.com/yanai-sh/winmint/issues/119) already has the Learn host.
