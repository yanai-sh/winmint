# Spec: WinMint v2 Smoke vertical

**Date:** 2026-07-27  
**Updated:** 2026-07-28  
**Status:** Spec locked. Closed backlog index: [TICKETS](../TICKETS.md).  
**Authority:** CONTEXT, DESIGN (grill), ARCHITECTURE, STACK, ADR-001–004, design/*  
**Destination:** Hyper-V Smoke green — Shell tenure splash + DMA hard-field evidence

## Problem Statement

WinMint needs a greenfield ISO → unattended Hyper-V install → FirstLogon path that users and maintainers can trust. Today’s pain is guest/runtime reliability (Explorer before splash, DMA settle races, sticky intermediate failures), not host Profile typing. Smoke must prove plumbing with the same product standards bare metal will use — not a Hyper-V-only fork.

## Solution

Ship a clean-sheet v2 stack: unelevated C# Orchestrator/CLI (**BuildPlan**), thin elevated host PowerShell Servicing (**ImageServicing** adapters), and a single Native AOT Provisioning Supervisor (**ProvisioningSession**: `--machine-setup` + Winlogon Shell). In-process splash, DMA settle by final snapshot, C# child-process provisioning jobs, Shell-tenure lock, checkpoint reboot, fail-open to Explorer. No guest PowerShell. Smoke uses the fast image-quality lane and a stub job set; the executor and settle rules match production.

## Constraints (not build tickets)

These are standing product rules. Do not file as feature tickets; enforce in acceptance and ADRs.

- **Source ISO** is always user-supplied ([ADR-001](../decisions/ADR-001-source-iso-legal.md)).
- **No Avalonia / WebView2 / WinUI on the ISO** — guest UI is the Supervisor’s in-process splash only.
- **No guest PowerShell** as FirstLogon control plane; **no peer Splash.exe**.
- **No in-process DISM** as the default imaging path (elevated `pwsh -File` Servicing).
- **No v1 topology copy** — harvest invariants/evidence ideas only ([ARCHITECTURE harvest rule](../ARCHITECTURE.md#v1-harvest-rule)).
- **No empty reserved trees** (`servicing/`, `schemas/`, `tools/`) until the ticket that needs them.
- **No Servicing port type** until prod `pwsh -File` and a test fake share a shape.
- **Smoke accounts:** Local + autoLogon only (password required).
- **Hyper-V Smoke SKU:** Pro only.
- **Acceptance Profile:** DMA on (schema may allow off; covered in S1 tests).
- **Image quality public names:** `Test` | `Release`.
- **Durable guest state:** `%ProgramData%\WinMint\`.
- **Grill locks:** [DESIGN.md](../DESIGN.md#decisions-locked-grill).

## User Stories

1. As a maintainer, I want a clean-sheet Profile + unattend/job JSON contract, so that Smoke builds are not tied to v1 BuildProfile/InstallPlan.
2. As a maintainer, I want an unelevated C# CLI to validate a Profile and plan a build (emit unattend/job JSON), so that elevation stays limited to imaging kernels.
3. As a maintainer, I want thin elevated Servicing kernels to mount/stage/export and stamp Shell offline, so that the guest binary is present before first logon.
4. As an installer (Local+autoLogon), I want Machine setup to stamp my account and verify Shell → Supervisor, so that I never hang on `defaultuser0` / “Just a moment.” Machine setup also **removes** leftover OOBE `defaultuser0` so the lock-screen picker is Profile-only.
5. As an installer, I want the first session UI after auth to be the WinMint splash (Supervisor as Shell), so that Explorer is not the first paint.
6. As an installer with DMA on, I want visible locale/GeoID/time zone restored before installs, so that Ireland Setup does not leak into daily use.
7. As an installer, I want location-services mismatches to warn without blocking FirstLogon, so that flaky location posture does not skip useful work.
8. As an installer, I want hard DMA settle failure to show a failed splash then unlock Explorer, so that I am not trapped without evidence.
9. As a maintainer, I want provisioning jobs driven as child processes by the Supervisor, so that Smoke and metal share one executor.
10. As a Smoke runner, I want a stub job set (no real WSL on the **acceptance/Smoke** Profile), so that Hyper-V acceptance stays plumbing-focused. (Metal Profiles may list `packages.wsl` — ticket **23**; that is out of Smoke’s stub story.)
11. As an installer, I want reboot-required work to checkpoint and keep Supervisor as Shell, so that splash resumes without an Explorer flash.
12. As an installer, I want unlock on complete/failed/timeout, so that Shell tenure always ends.
13. As a maintainer, I want in-memory splash status plus JSON evidence snapshots, so that a VM harness can pull proof without a file control plane.
14. As a Smoke runner, I want fast image-quality builds by default (run override), so that iteration is not blocked by Max compression.
15. As a maintainer, I want Hyper-V Smoke acceptance to assert splash + DMA hard fields (+ unlock), so that plumbing green means real settle success.

## Implementation Decisions

- Deep modules: **BuildPlan** (Orchestrator), **ImageServicing** (Orchestrator → `servicing/`), **ProvisioningSession** (Supervisor). Cli/Wizard are hosts of BuildPlan only. See [ARCHITECTURE](../ARCHITECTURE.md#deep-modules-product-seams).
- Product languages: C# for CLI, Orchestrator, and all guest FirstLogon/Machine setup; PowerShell 7.6+ for host Servicing only.
- One guest AOT binary: `WinMint.Provisioning` (`--machine-setup` and Shell share one phase machine); splash in-process (Direct2D/GDI with fallback).
- Shell registration: Servicing stamps offline; Machine setup fail-closed verifies/restamps (with autologon stamp).
- DMA settle: bounded restore then final snapshot; hard locale/GeoID/TZ; soft location; same Smoke and metal.
- Provisioning jobs: Supervisor runs winget/Scoop/wsl (etc.) as child processes; **Smoke** acceptance Profile uses the stub job set.
- Status: in-memory for paint; JSON snapshots are evidence projections only — not a control-plane mailbox.
- Fail-open: unlock on `complete`/`failed` (short failed dwell) and wall-clock timeout; hold Shell on `reboot` with durable checkpoint.
- Theme: splash-owned canvas; apply Profile appearance once before Explorer unlock.
- Provisioning lock: Shell tenure; hard input lockdown later, not Smoke-critical.
- Image quality: run override on BuildPlan/run options; Smoke uses fast lane; report records what ran.
- Clean-sheet Profile/unattend/job contracts; no v1 schema migration; prefer one contract surface over v1’s many near-duplicate JSON schemas.
- ImageServicing port (C# → elevated `pwsh -File`) appears when the first kernel and a test fake share a shape — not day-one; until then call `pwsh -File` from one Orchestrator path.
- NuGet Microsoft-thin (source-gen JSON, System.CommandLine, xUnit); Avalonia later for host wizard only.
- Cli already ProjectReferences Orchestrator; BuildPlan types land in ticket 01 (do not grow planning logic in Cli).

## Testing Decisions

- Test external behaviour through module interfaces, not private method structure.
- Prefer few high seams: (1) **BuildPlan** Profile/plan/unattend contracts; (2) **ProvisioningSession** phase machine (settle → jobs → unlock/reboot); (3) Hyper-V Smoke acceptance evidence (highest product seam).
- Unit/contract tests for BuildPlan and settle/job phase rules where deterministic; wire `WinMint.Tests` → Orchestrator when BuildPlan types exist.
- VM Smoke proves: Machine setup stamps, Shell tenure splash, DMA hard fields green (or failed path with evidence), unlock, fast-lane ISO used when configured.
- Ticket 10: one acceptance harness interface (“run Smoke → evidence”) with thin Hyper-V scripts behind it — not a peer forest of top-level entrypoints.
- Prior art: v1 VM acceptance evidence folders and contract suites — behaviour reference only; new schemas in v2.
